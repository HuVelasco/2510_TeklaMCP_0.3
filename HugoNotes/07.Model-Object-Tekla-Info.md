**Remarks**:

One way to find out the correct names of the report properties is to open the Template Editor. With the Template Editor you can see the listing of all the properties that can be added to report templates.

**Examples**:

In the following example a connection to the Tekla Structures model has already been established and next the values of some user-defined attributes (UDAs) are going to be found out. The UDAs asked are the string value of CHECKED_BY, the double value of CHECKED_DATE, and the integer value of OBJECT_LOCKED.
```
Copy
using Tekla.Structures.Model;
using System;
using System.Windows.Forms;

public class Example
{
       public void Example1()
       {
           Model Model = new Model();

           ModelObjectEnumerator ObjectEnum = Model.GetModelObjectSelector().GetAllObjects();
           ObjectEnum.SelectInstances = false; // Set the "SelectInstances" to false to speed up the enquiry; possible because only report properties are asked.

           string Result = "CHECKED BY, CHECKED DATE, OBJECT LOCKED \n";
           while(ObjectEnum.MoveNext())
           {
               if(ObjectEnum.Current != null)
               {
                   Beam BeamObject = ObjectEnum.Current as Beam;
                   if(BeamObject != null)
                   {
                       string CheckedBy = "";
                       double DateCheckedValue = 0.0;
                       int LockedStatus = -1;

                       DateTime DateChecked = new System.DateTime(1970, 1, 1);

                       BeamObject.GetUserProperty("CHECKED_BY", ref CheckedBy);
                       BeamObject.GetUserProperty("CHECKED_DATE", ref DateCheckedValue);
                       BeamObject.GetUserProperty("OBJECT_LOCKED", ref LockedStatus);
                       if(CheckedBy.Length > 0 || DateCheckedValue > 0.0 ||
                           LockedStatus != -1)

                       DateChecked = DateChecked.AddSeconds(DateCheckedValue);
                       Result += CheckedBy;
                       Result += ", ";
                       Result += DateChecked.ToString("dd.MM.yyyy");
                       if(LockedStatus == 1)
                       {
                           Result += ", Locked\n";
                       }
                       else
                       {
                           Result += ", Not locked\n";
                       }
                   }
               }
           }
           MessageBox.Show(Result);
       }
}
```

#### Position Class
The Position class defines how a part is positioned relative to the input.
https://developer.tekla.com/doc/tekla-structures/2025/position-class-53239#

The folowing position values are valid only when the work plane is the GLOBAL workplane,
see more info in the link: https://developer.tekla.com/documentation/coordinate-systems-and-work-planes
CoordinateSystem DefaultCoordinateSystem = new CoordinateSystem(new Point(), new Vector(1, 0, 0), new Vector(0, 1, 0));

Default for Tekla Beams: Beam().Position = MIDDLE, TOP, BEHIND.    Offsets = 0.0, 0.0 , 0.0  (top flange alligned in the same level regardless of the beam depth)
Default for other beams like columns and braces: Beam().Position = MIDDLE, TOP, MIDDLE.    Offsets = 0.0, 0.0 , 0.0 ( Centered )

Note: when the user asks you to set the position to MIDDLE, TOP, BEHIND, the user is seeing the Order as follows:
Position.PlaneEnum.MIDDLE
Position.PlaneOffset = 0 
Position.RotationEnum.TOP
Position.RotationOffset = 0
Position.DepthEnum.BEHIND
Position.DepthOffset = 0



<Position_Example>:
           Beam MyBeam = new Beam();

           MyBeam.Position.Depth = Position.DepthEnum.MIDDLE;
           MyBeam.Position.DepthOffset = 0;
           MyBeam.Position.Plane = Position.PlaneEnum.MIDDLE;
           MyBeam.Position.PlaneOffset = 0;
           MyBeam.Position.Rotation = Position.RotationEnum.FRONT;
           MyBeam.Position.RotationOffset = 0;
</Position_Example>

Some equivalencies with etabs insertion point
Insertion point, Tekla Position
    - 1-3: Bottom row (left, center, right) = (Position.PlaneEnum.LEFT, Position.PlaneEnum.MIDDLE, Position.PlaneEnum.RIGHT), Position.RotationEnum.TOP, Position.DepthEnum.FRONT
    - 4-6: Middle row (left, center, right) = (Position.PlaneEnum.LEFT, Position.PlaneEnum.MIDDLE, Position.PlaneEnum.RIGHT), Position.RotationEnum.TOP, Position.DepthEnum.MIDDLE
    - 7-9: Top row (left, center, right) =  (Position.PlaneEnum.LEFT, Position.PlaneEnum.MIDDLE, Position.PlaneEnum.RIGHT), Position.RotationEnum.TOP, Position.DepthEnum.BEHIND
    - 10: Centroid = Alligned with the centroid of the section, typically Centered for double symmetric sections, but needs some adjustment for non-symetric sections.
    - 11: Shear center = Alligned with the shear center

    Note: we need to capture the actual poistion in the UBIM format, but the application of the ceentroid and shear centered positions must have an option to ignore it and simply allign the position at the center (middle, front, middle)

  Rotation:
    Local Angle in Etabs is the equivalent of:
    Position.RotationEnum.TOP (default, similar to rotation = 0)
    and Position.RotationOffset = local_axis_from_etabs
    and we also have the folowing equivalencies so the mcp can understand the model:
    - Position.RotationEnum.TOP, Position.RotationOffset: 0 (degrees) = Position.RotationEnum.TOP (default)
    - Position.RotationEnum.TOP, Position.RotationOffset: 90 (degrees) = Position.RotationEnum.BACK
    - Position.RotationEnum.TOP, Position.RotationOffset: 180 (degrees) = Position.RotationEnum.BELOW
    - Position.RotationEnum.TOP, Position.RotationOffset: 270 (degrees) = Position.RotationEnum.FRONT



    1. UBIMProperties: OK
  2. UBIMOrientation: We dont need it, this os not part of etabs or Tekla.delete it
  3. cardinal_point (1-11): See notes below
  4. local_angle: See noes below
  5.  design_orientation, - ETABS classification: "column", "beam", or "brace"
    : This is not a geometric property, but a classification property. 
    - Use it to name the Tekla Objects as BEAM, COLUMN, BRACE or OTHER, 
    - Do not add prefixes postfixes to identify indiviual elements like 25_COULMN or COLUMN_25
    - Use optional general classifications like BEAM SECONDARY, BEAM MAIN, BRACE HORIZONTAL, BRACE VERTICAL, etc. this is optional and user defined.
    - Use a different class for each type and subtype, class = 1, 2, 3, 25, 69, etc. it can be any number,
  6. UBIMOffsets
  we dont need it for export reasons, Etabs calculates the offsets based on the connected object like the face of the column, but Tekla doesn't use it, we need to import all the frames start/end points where they are originally.
