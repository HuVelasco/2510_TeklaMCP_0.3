## System Overview

### Architecture Pattern
**FastMCP + HTTP + Controller Pattern**
- **FastMCP Server (Python)**: Claude interface layer with semantic tools
- **HTTP Server (C#)**: Routing and infrastructure layer
- **Controllers (C#)**: Business logic and Tekla API integration
- **Models (C#)**: Data transfer objects and shared utilities

### Data Flow
```
Claude → FastMCP Tools → HTTP Requests → C# Router → Controllers → Tekla API → Model Changes
```

### Core Principles
1. **Separation of concerns**: HTTP infrastructure separate from business logic
2. **Controller pattern**: Domain-specific controllers for scalability
3. **Single responsibility**: Each component has one clear purpose
4. **Progressive enhancement**: Build from basic to advanced features

## Phase 1: Basic Server Setup

### Minimum Viable Implementation

#### File Structure (Phase 1)
```
project/
├── mcp_server.py              # FastMCP tools (2 basic tools)
├── http_server.cs             # HTTP server infrastructure
├── elements_controller.cs     # Basic element creation
└── models/
    └── request_models.cs      # Data transfer objects
```

### Core Components

#### 1. mcp_server.py
**Purpose**: Provide Claude interface with semantic tools
**Responsibilities**:
- Define MCP tools with clear descriptions
- Handle parameter validation
- Make HTTP requests to C# server
- Format responses for Claude

**Key Functions**:
```python
@mcp.tool("create_beam")
def create_beam(start_x, start_y, start_z, end_x, end_y, end_z, profile, material)

@mcp.tool("create_column")  
def create_column(x, y, base_z, height, profile, material)

def _call_endpoint(endpoint, payload)  # Internal HTTP client helper
```

#### 2. http_server.cs
**Purpose**: HTTP infrastructure and request routing
**Responsibilities**:
- HTTP listener setup and lifecycle
- Request parsing and routing
- Response formatting
- Error handling infrastructure
- CORS handling if needed

**Key Components**:
```csharp
class HttpServer
{
    private HttpListener listener;
    private ElementsController elementsController;
    
    public void Start()                    # Server startup
    private void HandleRequest(context)    # Route requests to controllers
    private void SendResponse(response)    # Format and send HTTP responses
}
```

#### 3. elements_controller.cs
**Purpose**: Handle element creation operations
**Responsibilities**:
- Tekla Model connection management
- Element creation logic (beams, columns, braces)
- Parameter validation
- Tekla API error handling

**Key Functions**:
```csharp
public class ElementsController
{
    private Model model;
    
    public object CreateElement(ElementRequest request)
    public object GetElementInfo(int elementId)
    private bool ValidateConnection()
}
```

#### 4. models/request_models.cs
**Purpose**: Data transfer objects and shared utilities
**Components**:
```csharp
public class ElementRequest
{
    public string ElementType { get; set; }  // "BEAM", "COLUMN", "BRACE"

}
```

### Controller Responsibilities

#### elements_controller.cs
**Domain**: Individual structural elements
**Endpoints**:
- `POST /elements/create` - Create any element type
- `GET /elements/{id}` - Get element properties
- `PUT /elements/{id}/modify` - Modify element properties
- `DELETE /elements/{id}` - Delete element

#### connections_controller.cs
**Domain**: Connections between elements
**Endpoints**:
- `POST /connections/create` - Create connections
- `POST /connections/create-by-ids` - Create connection by element IDs
- `GET /connections/{id}` - Get connection details

#### utilities_controller.cs
**Domain**: Documentation, patterns, and utilities
**Endpoints**:
- `GET /docs/patterns/{topic}` - Get Tekla API patterns
- `GET /docs/examples/{elementType}` - Get code examples
- `POST /utils/execute-code` - Code executor
- `GET /utils/profiles` - Available steel profiles

### Advanced Controllers

#### workflow_controller.cs
**Purpose**: Handle complex multi-step operations
**Capabilities**:
- Batch element creation
- Conditional operations
- Multi-model operations
- Transaction-like operations with rollback

**Key Endpoints**:
```
POST /workflow/batch-create        # Create multiple elements atomically
POST /workflow/import-and-classify # Import model and apply classifications
POST /workflow/execute-sequence    # Execute operation sequence
GET /workflow/templates            # Available workflow templates
```

**Example Operations**:
- Import ETABS model → Create elements → Classify by location
- Create structural grid → Place columns → Add beams → Connect all
- Analyze existing model → Suggest connections → Create connections

#### import_controller.cs
**Purpose**: Handle external model imports
**Supported Formats**:
- ETABS models
- SAP2000 models  
- IFC files
- CSV/Excel element lists

**Endpoints**:
```
POST /import/etabs               # Import ETABS model
POST /import/csv-elements        # Import from CSV/Excel
GET /import/preview/{importId}   # Preview import before execution
POST /import/execute/{importId}  # Execute previewed import
```

## Development Guidelines

### Coding Standards

#### Python (FastMCP Server)
- Use type hints for all function parameters
- Include comprehensive docstrings for all MCP tools
- Handle HTTP errors gracefully
- Use consistent naming for similar tools

#### C# (HTTP Server & Controllers)
- Follow controller pattern consistently
- Use proper async/await for I/O operations
- Implement comprehensive error handling
- Use dependency injection where appropriate
- Always call `model.CommitChanges()` after Tekla operations

### Error Handling Strategy

#### Python Layer
- Catch HTTP connection errors
- Validate parameters before sending requests
- Return structured error responses

#### C# Layer
- Validate Tekla connection before operations
- Catch and translate Tekla API exceptions
- Use structured error responses with error codes
- Log errors for debugging

### Testing Strategy

#### Unit Testing
- Test each controller independently
- Mock Tekla Model for testing
- Test parameter validation
- Test error conditions

#### Integration Testing
- Test full MCP → HTTP → Tekla flow
- Test with actual Tekla model
- Test batch operations
- Test import operations

### Performance Considerations
- Cache Tekla model connection
- Batch operations where possible
- Use async operations for I/O
- Monitor memory usage with large imports
- Implement connection pooling if needed

### Security Considerations
- Validate all input parameters
- Sanitize file paths for imports
- Limit code executor scope
- Use HTTPS in production
- Implement authentication if needed
